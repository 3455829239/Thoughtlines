# Thought Radar

Thought Radar 是本地运行的单项目工作台。它根据用户确认纳入的聊天提取探索问题和思考节点，让用户查看证据、审阅草稿并将结论合并到 Main。

## 启动

需要 Node.js 22.12 或以上版本。在项目根目录运行以下命令。

```powershell
npm ci
npm run dev
```

打开 [本地工作台](http://127.0.0.1:4173)。此时可以创建项目、导入聊天、使用本地召回和查看原文。

当项目目录包含随本地演示准备的两份「信息整理问题总结」JSON 时，空白工作台首次启动会自动读取两份文件，并直接展示有原文引用的探索图和合并草稿。此结果标记为「本地整理」。已有项目会保留，使用 `THOUGHT_RADAR_DATA` 指定独立存档时仍可从空白工作台开始。

如果再次启动时提示端口 4173 已被占用，先打开工作台地址。工作台已在运行时，直接使用即可。

### 自检

在本机 PowerShell 进入项目目录并运行自检。自检读取本地配置和工作台状态，无需先启动服务，也不会显示密钥。

```powershell
Set-Location -LiteralPath 'D:\coding\Thoughtlines'
npm run doctor
```

- 显示「已运行」时，直接打开输出的工作台地址。
- 显示「没有可连接的服务」且依赖就绪时，运行 `npm run dev`。
- 提示检查端口占用时，用 `Get-NetTCPConnection -LocalPort 4173 -State Listen | Select-Object LocalAddress,OwningProcess` 查看监听地址与进程 ID。配置了其他端口时，将 4173 替换为自检输出的端口。

使用 AI 时，在本机编辑 `server/.env`，填写 `OPENAI_API_KEY` 并确认 `OPENAI_MODEL`。若文件缺失，可从 `server/.env.example` 复制一份。配置文件会被 Git 忽略。

```powershell
npm run check:model
```

检查命令只查询模型信息，不发送聊天或生成内容。检查通过后重启工作台，以加载新配置。使用主办方的 OpenAI 兼容服务时，将文档提供的 API 前缀填入 `OPENAI_BASE_URL`，运行 `npm run list:models` 查询模型 ID，再设置 `OPENAI_MODEL`。旧的 `LLM_*` 连接配置仍受支持。模型需要支持 Chat Completions、结构化 JSON 和本次分析规模的输入。

生产模式与测试：

```powershell
npm run build
npm start
# 自动化测试
npm test
```

## 验证流程

1. 输入项目名称和目标，建立 Main v1。
2. 在「导入聊天」中选择一个或多个导出文件，查看导入报告和对话路径。
3. 点击「AI 判断相关性」，查看推荐理由和对应消息。勾选或排除推荐项，也可以按标题搜索并手动补充。
4. 点击「确认范围并分析」。选择图中的思考节点，在右侧展开原始聊天证据。
5. 打开一条有证据的合并草稿，点击「确认合并」或「拒绝」。一次确认生成一个新版本。点击 Main 节点可查看对应的版本快照。

## 数据与范围

- 支持官方 `conversations.json` 的 `mapping` 路径，以及工作目录内已有的 `metadata + messages` 线性导出。线性导出缺少逐条时间和平台消息 ID，工作台保留缺失时间并生成稳定的本地 ID。
- 单文件上限为 100 MB。导入时只读取原文件，归一化聊天和工作台状态保存在 `data/workspace.json`。启动路径可通过 `THOUGHT_RADAR_DATA` 指定。使用单个服务进程写入同一存档。
- AI 相关性判断最多发送 12 段候选，每段 1,000 字符。分析最多发送 8 段已选聊天，每段 5,500 字符。每次操作最多调用一次模型。分析还会发送项目目标和 Main 每栏最近最多 25 项。
- 源聊天按需展示全文。模型只收到采样片段，长讨论或少量内容支持的结论可能被遗漏。模型返回的来源 ID、所属聊天、提交关系和问题依赖必须通过校验。
- 模型超时、返回错误或输出无效时，工作台显示错误并允许重新发起操作。工作台仅监听本机，聊天片段只在发起 AI 操作时发送给所配置的模型服务。
- 证据不足时，分析可以产生较少的分支、提交和提案。正式 Main 仅在用户批准合并后变化。
